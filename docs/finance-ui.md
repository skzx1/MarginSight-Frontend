# หน้าการเงิน — 18 ตุลาคม 2026

## หน้าที่และเส้นทาง

`/login/#finance` อยู่ระหว่างสินค้าและถามผู้ช่วย เมนูหลักห้ารายการยังใช้ได้ที่ 390px และ iPad จึงไม่ซ้อนเมนูเพิ่ม หน้านี้ใช้พื้นที่ข้าง drawer เต็มความกว้าง สูงสุด 1920px โดยยังใช้สี ฟอนต์ และส่วนประกอบเดิม

ช่วงเวลาใช้ state และ `OverviewPeriodControl` เดียวกับ Overview; date boundaries ใช้ Bangkok helpers เดิม ทุกส่วนใช้ชุดข้อมูลหลังกรองช่วงเวลาและช่องทางเดียวกัน ส่วนค้นหา/สถานะเป็นตัวกรองรายการออเดอร์เท่านั้น CSV ส่งออกทั้งรายงานในช่วงเวลาและช่องทางที่เลือก ไม่ตัดยอดรวมตามข้อความค้นหา

มี KPI 6 ค่า, งบกำไรขาดทุน, กราฟเดียวสลับกำไร/ยอดขายกับค่าใช้จ่าย/มาร์จิน, ตารางช่องทางพร้อมมาร์จินสูงสุด, ออเดอร์, สินค้ากำไรสูงสุด/ต่ำสุด และค่าใช้จ่าย มีลิงก์ข้ามส่วนโดยไม่เปลี่ยน hash route กราฟมีตารางตัวเลขและตัวเลือกวันที่สำหรับคีย์บอร์ด

## ข้อมูลจำลองที่เพิ่ม

`finance-mock.ts` ขยายข้อมูลสินค้าจาก `INITIAL_MOCK_PRODUCTS` เป็นชุดสาธิตการเงินแยกต่างหาก ไม่แทนที่ออเดอร์ของ Overview หรือข้อมูลนำเข้า:

- 310 ออเดอร์ใน 62 วันล่าสุด ครบ Shopee, Lazada, TikTok Shop, LINE Shop และหน้าร้าน
- สถานะสำเร็จ/รอ/ยกเลิก/คืนสินค้า ส่วนลด ค่าธรรมเนียม ค่าจัดส่ง ค่าแพ็ก และค่าโฆษณาเป็นข้อมูลสังเคราะห์ที่กำหนดไว้ ไม่ใช่อัตราตลาด
- ออเดอร์ตัวอย่างหนึ่งสินค้าต่อรายการเพื่อแสดงกำไรสินค้าที่มีหลักฐานครบ
- ใช้ `calculate` จาก generated contract เดิมเท่านั้น ไม่แก้สูตรหรือ artifact ออเดอร์มีค่าธรรมเนียมบันทึกชัดเจนรวมถึงศูนย์
- Pending/cancelled ยังไม่รับรู้ยอดขาย; returned ตัวอย่างคืนเต็มจำนวนและคืนต้นทุนครบ ไม่อ้างว่าครอบคลุมเหตุการณ์คืนสินค้าทุกแบบ
- วันที่เดียวกันให้ข้อมูลเหมือนเดิมเมื่อช่วงตัวอย่างเลื่อนไปวันถัดไป
- หน้าแสดงช่วงที่มีชุดตัวอย่าง หากช่วงเปรียบเทียบอยู่นอกข้อมูลครบ 62 วัน จะไม่แสดงเปอร์เซ็นต์เปรียบเทียบ

`finance-data.ts` รวมยอดรายการที่บันทึกเป็นจำนวนเต็มสตางค์ ใช้ `summarizeOrders` เดิม ค่าใช้จ่ายเพิ่มเติมหักจากผลกำไรที่ engine/API ส่งมา ไม่คำนวณค่าธรรมเนียมหรือกำไรออเดอร์ซ้ำ ยอดขายใน KPI เป็นยอดสุทธิหลังส่วนลด/คืนสินค้า; AOV หารด้วยออเดอร์ทุกสถานะ ตามคำอธิบายในหัวข้อ KPI

## ข้อมูลจริงและข้อจำกัด API

ร้าน REAL ใช้ `useOverviewDashboard` อ่าน snapshot รายเดือน ครอบคลุมช่วงเลือกและช่วงก่อนหน้าที่มีจำนวนวันเท่ากัน ใช้ผลจาก API เท่านั้น:

- API ยังไม่แยก gross sales/discounts/returns จึงแสดง — สองบรรทัดแรก และอธิบายว่า API ให้ net sales แล้ว
- สถานะคำนวณไม่ใช่สถานะการขาย จึงแสดงสถานะออเดอร์ว่าไม่มีข้อมูล แทนการเดาว่า COMPLETED
- กำไรสินค้าจากออเดอร์หลายสินค้าต้องรอ item-level profit จาก API ไม่จัดสรรกำไรด้วยสูตรใหม่
- ค่าใช้จ่ายประจำและภาษีที่ไม่ได้บันทึกไม่รวมในกำไร
- ข้อมูลต้นทุนขาดแสดง callout ไปหน้าสินค้าที่กรอง missing cost และใช้ — สำหรับกำไรที่ยังสรุปไม่ได้ ไม่ตีความ unknown เป็นศูนย์
- ส่วนเพิ่มค่าใช้จ่ายเปิดเฉพาะ MOCK จนกว่าจะมี save API ของร้านจริง

## ค่าใช้จ่ายและ CSV

รายการเพิ่มเก็บใน `localStorage` ภายใต้ `marginsight:finance-expenses:v1:<SHA-256>` แยกด้วยบัญชี/รอบเดโมและร้าน โดยใช้ scope helper เดิม ไม่เก็บ token ใน localStorage ไม่ส่งข้อมูลไป backend

รายการต้องมีหมวดหมู่ จำนวนเงินบวกไม่เกิน 1,000 ล้านบาท วันที่จริง และช่องทาง หมายเหตุไม่เกิน 240 ตัวอักษร สูงสุด 1,000 รายการ ไม่เขียนทับข้อมูลเก่าที่อ่าน/ตรวจ schema ไม่ผ่าน บันทึกไม่สำเร็จเก็บร่างไว้ ค่าใช้จ่ายรวมเข้าช่องทาง วันที่ งบ KPI และกราฟอย่างสอดคล้อง สินค้า/ออเดอร์แสดงกำไรก่อนค่าใช้จ่ายที่ไม่ได้ผูกสินค้า มีคำอธิบายไว้ในหน้า

CSV มี UTF-8 BOM พร้อมช่วงเวลา ช่องทาง หน่วยและที่มาข้อมูล KPI งบ ช่องทาง ออเดอร์ สินค้า แนวโน้มรายวัน ค่าใช้จ่าย และค่าช่วงก่อนหน้าเมื่อเปิดเปรียบเทียบ Escape เครื่องหมายคำพูด/newlines และป้องกัน spreadsheet formula ในข้อความ ค่าติดลบที่เป็นตัวเลขยังส่งออกเป็นตัวเลข
